## Model readiness

The unchanged signed model bundle was profiled twice at its original URL and twice at a relocated URL, each in a separate process. The original path took **12.81 s** and **133 ms**. The relocated path took **18.02 s** and **397 ms**. In the slow relocated run, **16.39 s** was inside the encoder’s `MLModel.load`. The associated first inference took **91 ms**. The original path’s slow load also fell in the encoder call. The pattern supports an uncached device specialization versus a cache hit, consistent with Apple’s documented path- and configuration-dependent cache. The exact reason for eviction in the earlier 19.5-second case could not be observed. The Instruments CLI recorded the launch but failed to export the model activity because it lacked the trace template. [Original first launch](results/final/load-original-1.jsonl) · [Original repeat](results/final/load-original-2.jsonl) · [Relocated first launch](results/final/load-relocated-1.jsonl) · [Relocated repeat](results/final/load-relocated-2.jsonl) · [Apple Core ML integration](https://developer.apple.com/videos/play/wwdc2023/10049/?time=429)

The study now keeps one portable model for a bounded **180 seconds** after use, sustains the ready model on Cancel, and drops it on expiration, system sleep or memory pressure. Cancelled jobs drain before another portable native decode starts. Concurrent preparation callers share one load, and a stale expiration cannot evict a renewed model. The installed app keeps a fixed path. Preparation remains explicit or overlaps the recording. When finalization is waiting on the model, **Preparing speech** explains the delay and Cancel stays available. The app keeps the microphone independent of model work.

At the old one-minute cutoff plus 15 seconds, the model was still prepared, with a **0.14 ms acquisition**, **128 ms total decode** and **40 MB process footprint** in the measured 75-second run. Across 12 complete warm fixture captures, median Finish-to-text was **180 ms**, median SQLite commit was **1.8 ms**, and every capture was saved once. The updated fixed-path app still reproduced a **13.32 s** initial load after installation. Core ML specialization remains OS-owned and can recur after eviction, first use or relocation. The study never copies private cache files, keeps multiple prepared engines, or silently switches compute policy. ## Fidelity

The unchanged configuration, 80 ms of extra leading silence, and a CPU-only encoder with the other model components on the existing policy were compared on the 23 development fixtures and the locked 168-clip human holdout. Combined errors per cohort use the same word normalization as Round 3.

| Configuration | English meetings | Portuguese conversation | Read PT–EN switching |
|---|---:|---:|---:|
| Fluid default | 13.00% | 21.82% | 8.89% |
| 80 ms leading silence | 14.05% | 24.13% | 8.89% |
| CPU encoder | 14.26% | 21.69% | 8.89% |

CPU encoder transcripts matched in 157 of 168 cases. Differences included apparent extra English content on an overlapping meeting turn and on a Portuguese fragment. All variants made the same polarity-changing error in the known meeting warning. The short no-deploy and Portuguese boundary fixtures retained their negation with the selected profile. The uncertainty, correction and mixed technical development cases provide useful controls, and additional leading silence provided no reliable gain. The selected audio path preserves real sample order, normalizes only invalid numeric samples, and retains the existing one-second minimum handling for TDT. The app preserves the literal transcript and offers review. Neither voice rewriting nor inferred negation was added. ## Engineering and interaction

- Keep commits the kept thought and clears its pending review in one SQLite transaction. The app reports success after that commit. Injected journal cleanup failure rolls back the note. Discard waits for an enqueued write, reports a failed deletion, and keeps the transcript visible for a retry. Reset drains pending scratch and evaluation exports before clearing study data. Filesystem cleanup runs outside the main actor.
- A post-start input stall retains any captured speech as an interrupted review. Route changes close the input even during the bounded tail. The finalized buffer is sealed against late callbacks. Activity measurement uses fixed windows across driver packet boundaries. Session tokens and serialized portable inference prevent stale async work from mutating another capture.
- Settings and the edit sheet suspend capture commands. Review stays visible through Keep and Discard. Device denial and restoration have distinct states. Setup failure never opens the microphone. The non-activating capsule retains the existing Rasc palette and Kept receipt. [Signed tests](results/final/validation.txt) · [Native focus observations](results/final/window-focus-runs.jsonl)

The signed test run exercises **18 scenario groups**, with **135 starts and stops** in its main fixture including 120 rapid cancellation cycles. It covers first grant, denial and revocation through injected system decisions, the 120 ms finish tail, input stall and route loss, timeout and stale completion, real SQLite transaction failures, duplicate Keep, reload recovery, and reset racing optional exports. Three isolated native focus reruns preserved the frontmost application, with a visible non-key panel. One run with other validation processes in flight observed a frontmost change while the panel remained non-key. The live native accessibility tree exposed Start, the engine selector, and the default Review mode. The capture shortcut left the settings sheet open, and Prepare Speech returned to ‘Speech is ready.’ Separately, all three engines transcribe the English and Portuguese fixtures with network interfaces down. Real hardware microphone metadata is documented in Round 3. The final build leaves the genuine OS microphone grant for the person using the study. Neither production signing nor TCC storage was modified.
