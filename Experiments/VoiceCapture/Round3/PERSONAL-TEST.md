# Try Rasc Voice Capture

Open the signed [Rasc Voice Capture.app](<Study/Build/Rasc Voice Capture.app>). It uses its own scratch and database. **Fluid Speech Pro**, **press to start and finish**, and **review before Keep** are the defaults. The two portable engines are bundled. The first Start may show macOS microphone access. Allow it, then start again and wait for **Listening**. macOS remembers this grant for the installed signing identity.

## First capture

1. Leave an unfinished sentence in **Scratch**. Start a recording and speak a short disposable thought. Make a natural pause. Finish, inspect the original transcript and correct only what matters. Keep with **⌘↵**. Open the kept thought, try Edit, then start a second capture to try Undo. The scratch stays independent.
2. Open **Study Options**. If you prefer a shortcut, turn it on and assign a free chord. Try **Keep with Open and Undo** while another app is active. The order is press, wait for Listening, speak, press again, and continue working. The small **Kept** receipt is temporary. The menu bar can still open or undo the last capture.
3. Switch to **Parakeet Ultra** and **Apple SpeechTranscriber** for comparison. Apple’s language is selected explicitly; prepare any missing language asset in Settings. **Prepare Speech** can warm a portable model before capture. If the model is still loading after Finish, the panel shows **Preparing speech**. The study uses the local model only when preparing or capturing.

## Compare a few real thoughts

Use harmless examples that reflect how you actually think. Check that the output keeps a hesitation, correction and the first and last word. Try a one-line correction such as “Não apaga isso ainda,” a mixed idea with a familiar technical term, and a longer unstructured thought. Finish promptly on one test and leave your usual pause on another. Try **Hold to speak** on a short phrase; compare the mental effort with toggle on a longer one. Hold the complete chord until you mean to finish.

For a meaningful everyday comparison, record which workflow produced a *correct saved thought and returned you to the prior app* first. Compare typing, macOS Dictation in Scratchpad, and the dedicated voice shortcut on different prompts of the same length. Include correction time. Keep the order varied and mark an attempt as lost if it never produced correct text. A brief note about when you preferred typing is more useful than a single elapsed time.

## Optional local results

**Save timing results locally** in Study Options records engine, language, duration, latency and outcome without text or audio. That option also reveals an explicit **Save recording locally** action in review and a separate **Save transcript comparison** approval after Keep. Use either only for disposable evaluation content and only if you intend to share or retain it yourself. The study uses clean room data during validation. It reads no production scratch or notes.

**Show Study Files** opens the isolated study folder. **Reset Study Data** asks for confirmation before removing this study’s notes, scratch and evaluation files. The normal draft and Kept flows do not export recordings. If macOS revokes microphone access, **Open Microphone Settings** takes you to the system setting. After allowing access, use **Try Again**.

## Remaining hands-on checks

Subjective shortcut comfort, natural personal code-switching, long thoughts during work, jobs with AirPods or other Bluetooth microphones, and real comparison against typing/Dictation still need a participant. Production release also requires real fullscreen, Spaces, separate display, VoiceOver, Reduce Motion, device-change and sleep checks under the shortlisted signing path.
