# Voice Capture for Rasc

**Decision on 2026-11-24: No-Go for production auto-Keep. Go for a small, reviewed dogfood study.** The best native candidate is fast enough to test with people. The experiment found substantial mixed-language errors and a change in meaning in a noisy Brazilian Portuguese fixture. A same-path replacement of an ad-hoc signed test bundle also lost its microphone grant. Both matter in a flow whose appeal is that users can finish and move on.

Voice Capture belongs beside the Scratchpad as an **optional capture method** if it demonstrates repeat use. Its strongest case is a thought that's easier to say than type, while the user keeps their place in another app. Compare it with Apple Dictation inside the existing Scratchpad. If voice saves little time after review and correction, the extra surface and release work have little product justification.

## 2. Product discovery

These are use hypotheses. No participants were recruited and frequency was not measured.

| Moment | Where voice can help | Where Scratchpad can win |
|---|---|---|
| Debugging or fullscreen work | Capture a tentative hypothesis over a fullscreen debugger, finish and keep looking at the same code. Find it in Home later without replacing the pending Scratchpad. Potentially common on debugging-heavy days if identifiers survive. | Typing or pasting gives exact symbols, stack traces, URLs and snippets. A busy office or a call makes speaking awkward. |
| Reading or watching | Keep the place in a PDF or on a paused video. Speak a question, stop, resume and retrieve it by phrase later. Potentially several times in a research session. | A quote, URL or page number is easier to copy. Audio from speakers contaminates the mic. Rasc should leave media controls alone. |
| Long or unformed thought | Think aloud, pause, correct an earlier phrase, and stop when the thread is captured. The value is a lower barrier to starting, for technical and nontechnical users. | Typing helps with expression that needs quiet, precise structure or rereading along the way. Mandatory review can erase the interruption benefit. |
| Typing is physically hard or only one hand is free | Press a comfortable chord or use a menu, speak hands-free, and get an accessible finish outcome. This could be the primary capture path for some people. | Holding a multi-key chord increases motor demand. Speech can itself be difficult or tiring. Preserve standard keyboard and accessibility paths. |
| Fleeting two-word thought | Ready mic and deliberate Finish can preserve a rapidly fading cue. | Two typed words often beat startup. A missing first word can change all of the meaning. |
| Shared or sensitive setting | Use voice when it is comfortable to speak. | On-device processing cannot stop another person from hearing what is spoken. Use Scratchpad in public or near confidential calls. |

Measure typing, system Dictation in Scratchpad, and independent capture on matched tasks. Include time to usable retrieval and correction, as well as the time away from the source. Use natural thoughts, pauses and unfinished drafts. Note access benefits separately from aggregate frequency.

## 3. Interaction comparison

| Approach | User tradeoff | Engineering consequence |
|---|---|---|
| **Toggle, independent panel** | Two intentional taps. Hands free through longer speech and pauses. Can leave recording on by forgetting Finish. Consistent status, cancel and a reasonable limit are important. | Guard each complete key cycle. Start with existing key-up convention. Measure whether key-down improves perceived readiness enough to justify difference. |
| **Push-to-talk** | Great physical boundary for a short burst. Holding while thinking, moving or typing is harder. Fast speakers can clip the first word while the device starts, and release can cut the last one. | Existing API supports press/release. Missed key-up, autorepeat, menu tracking, sleep, external keyboards and modifier-first release need tests and a watchdog. |
| **Hybrid** | One shortcut suits more thought lengths. The hold threshold introduces a mode users cannot always predict. Accidental activation and cancellation become context dependent. | Needs a timer plus a state model resilient to delays and mismatched release. Defer until a cohort demonstrates clear demand. |
| **Scratchpad-based capture** | Editor is familiar and inspectable. Opening it moves focus and adds review time. Good when editing is part of the same thought. | System Dictation already covers insertion. A dedicated path needs a clear, explicit destination when another thought is open. |
| **Menu-bar capture** | Discoverable, pointer-friendly and useful for failure recovery. Can be out of view in fullscreen or a crowded menu bar. | Reuse Rasc's status item alongside a visible recording surface. |
| **Live preview** | Useful to some for confirmation or accessibility. Other users can be drawn into editing, and their prose is more visible to onlookers. | Render finalized segments and one provisional range in a stable, solid view. Keep selectable review separate. |
| **System Dictation in Scratchpad** | Already available on eligible Macs. Manually Keep after speaking. | Comparison baseline and an older-OS path. User-invoked system Dictation has its own device and privacy policy. |

Test an **optional global toggle with a Rasc menu entry and a non-key floating capsule**. No stop on silence. Begin the microphone only after explicit invocation, assets and permission. Start in Preparing and mark Listening when the first usable buffer arrives. A mic symbol and text communicate state. A level indicator, if needed, must derive from actual samples and have a static reduced-motion alternative. The prototype uses a time label. Keep it only if testing shows that it provides orientation. Start with a 90-second trial limit, communicate it visibly near the end, and route the bounded recording to review on timeout.

## 4. Recommended experience

1. **Discover.** Add Voice Capture to the Rasc menu near New Thought on eligible systems, searchable in Command Palette. Offer an opt-in chord in the existing Shortcut settings and validate conflicts. Keep general onboarding centered on typing.
2. **Set up.** On first deliberate use, explain that speech processing is local and show the selected supported capture language. Offer a simple language choice independent of Refine. Ask permission in context. Keep model preparation and mic readiness distinct. Let users cancel a download, and require a deliberate Start when first-use setup finishes.
3. **Start.** Immediately acknowledge the chord with Starting microphone. Change to Listening on the first usable buffer. The user keeps focus. Avoid a default start sound. Provide a tested VoiceOver announcement and reveal Finish and Cancel in the menu if the small panel is inaccessible to keyboard focus.
4. **Finish.** The same chord, button or menu action stops input. Drain already captured frames to the stop boundary and finalize. Leave the mic off during this phase. Show Finishing transcription, then Saving if the write is observable. Do not infer Finish from pauses.
5. **Keep or review.** In the studied prototype, show verbatim editable text with explicit Keep. Test automatic Keep separately after quality gates pass. In that flow, show copper Kept only after commit. Give Open and Undo, and keep Open Last Capture and eligible Undo reachable from the Rasc menu after the brief receipt fades. Open uses existing flush-and-switch behavior only on an explicit action. Cue state through assistive tech without reading the private thought aloud until review is entered.
6. **Cancel or undo.** Cancel during prep, recording or finalization via buttons and menu, or Escape within a focused Rasc surface. Avoid a global unmodified Escape. If Full Keyboard Access cannot reach the menu while working elsewhere, test a temporary cancel chord tied to the configured shortcut. Once the atomic save has started, finish and offer Undo. Apply it only to this unmodified capture without moving the current editor.
7. **Recover.** Distinguish no speech, no usable transcript, missing assets, permission denial, route loss and database errors. With detected speech but no transcript, retain a bounded in-memory retry and offer Discard. Retain editable text for Retry Save and explicit Copy Text when the write fails. For interruptions retain the audio and finalized text available so far, clearly mark it incomplete and require review. Keep failure feedback available until resolved. Confidence cannot reliably detect a meaning change.

### What Finish should do

| Finish outcome | Decision |
|---|---|
| Keep every final nonempty string | Fewest steps, but an inaccurate final string or speech hallucination becomes a trusted note. The current data rule out this policy. |
| Keep and show an unobtrusive receipt | Best production hypothesis after fidelity qualification. Explicit Finish authorizes saving, while Open and Undo remain optional. |
| Always open a fresh review | Preferred research control. Reveals corrections and provides ground truth. Increases focus changes and can cost more than typing for short clips. |
| Review only on credible failure | Use with a qualified auto-Keep path for interruption, a dropped buffer, timeout or missing final results. These observable events are stronger than an engine's confidence or alternates. |
| Add a review preference | Hold until a real user cohort repeatedly needs a different default. Language choice and shortcut assignment already cover meaningful setup differences. |

Deterministic normalization should start with edge whitespace trim and suppression of empty results. Preserve punctuation, numerals, fillers, false starts and meaningful hesitations as emitted. Segment formatting may be necessary to preserve recognizer word boundaries. Keep rewriting and all existing Refine behavior user-invoked. Capture origin needs no saved source badge or category.

### Visual directions

- **Floating capsule.** A 268 × 48 pt recording surface with labeled mic, optional timer, Stop and Cancel. Kept shares its position, with small copper assurance and neutral Open/Undo. Solid palette-derived fill, quiet border and individually labeled actions.
- **Live thought.** A 375 pt solid transcript panel. A quiet provisional range sits below stable text. Add a bounded viewport if prototyping live emission. Avoid motion or constant accessibility announcements for each update. Study it for people who want immediate confirmation.
- **Menu bar.** Recording state and actions use Rasc's status item. This is the persistent recovery route and a useful alternative for mouse users. On its own it can be hard to see in fullscreen.
- **Scratchpad review.** Use the editor's typography, spacing and Keep action for a separate new thought or explicit review. Never replace an open editor on a recognition callback.

Start with the pointer display at lower center, above Dock and safe-area geometry, and retain it until the session ends or the display disconnects. Fall back to the available active screen. This heuristic needs a multi-display test for keyboard-driven flows when pointer and focus disagree. Ordinary recording panel stays non-key. Let permission/system dialogs take precedence. Test the floating window level in fullscreen rather than assuming the current Scratchpad's elevated configuration applies. If there is no reliable visual or accessibility indicator in a space, make that context an explicit compatibility decision. Respect Reduce Motion, Increase Contrast, Reduce Transparency and Custom themes. Never imitate or cover the system mic indicator.

## 5. Architecture

A small main-actor voice coordinator owns UI state, input controls and a single capture ID and generation. It runs audio/recognition and DB work off the main actor. Use a narrow adapter around one shipping engine. Avoid a general provider registry.

```text
idle → preparing → recording → finalizing → saving → kept
         │            │             │         │
       cancel       cancel        cancel    save failure → retry same ID
                      │             │
                   interruption    ASR failure → retry or review
```

- A complete key cycle is the unit of toggle. Ignore autorepeat, out-of-state presses and repeated Finish while finalizing/saving. Check the live generation after every await. Joining all cancellation work preserves resource ownership. A late threshold, asset callback or result cannot start a mic, update a newer panel or insert a row after cancel.
- Start AVAudioEngine only on a current, explicit activation. Copy frames to owned bounded storage before returning the tap callback. Avoid waiting, logging, disk I/O, and model work in the callback. Use one consumer to normalize via AVAudioConverter with a sample-clock cursor and bounded queue. Track frames, overflow and route discontinuity. Stop explicitly, drain accepted frames, flush conversion and explicitly terminate the analyzer sequence. Assemble finalized results by time range and replace provisional ranges that overlap.
- Use one UUID for capture and database identity. Add a repository method that validates meaningful text, inserts a plain Note with created/updated/kept timestamps in one GRDB transaction, and returns the persisted row. FTS updates in the transaction. An idempotent retry may return an existing matching Kept, undeleted row. A changed or discarded row yields stale failure. Never upsert over it. Verify clean reopen, ambiguity after commit, and fault rollback. Route Undo through an atomic compare-and-discard and existing soft-delete semantics.
- Keep tone, activeness, selection, refs, and onboarding in the existing application domains. Check initial scratch restoration before a background insert. Refresh Home and relevant Search on successful commit without disrupting selection or input. A completely independent voice capture should not require a pending Scratchpad write to succeed.
- Cancel stops the mic and invalidates generation, and finalization is bounded. On sleep, route loss, or hard cap, stop capture and offer partial review/retry. Quit coordinates with the existing termination guard and asks before discarding the only recoverable copy. After wake require a new user start.
- Report Kept only after commit or confirmed matching replay. Restore soundness beats a too-fast acknowledgment. A process can still terminate after commit and before showing UI, in which case the thought must be visible in Home on restart.

The isolated proof linked the current repository, domain types and migrations through a temporary extension. It verified same-ID concurrent replay, active scratch preservation, FTS, second-connection reads, injected write failure/retry and soft-discard behavior. Compare-and-discard Undo, native Home refresh, concurrency with a live editor and real termination remain integration gates.

## 6. Audio retention, privacy and recovery

| Approach | Decision |
|---|---|
| Stream without replay | Low overhead and immediate audio disposal. A recognizer interruption can lose the only source for a thought. Insufficient for the dogfood. |
| Bounded memory and in-session retry | Preferred. 90 seconds of mono PCM16 at 16 kHz is 2.88 MB, or 5.76 MB as Float32, before copies. Release audio when usable final text exists, on explicit discard/cancel, or after successful recovery. Keep the transcript on save failure. If the only copy remains in memory, make quit's consequence clear. A crash can still lose unsaved data. |
| Bounded local file | Can survive a crash. Adds storage permissions, cleanup, retention disclosure, backups and hard-to-guarantee physical erasure. Reconsider only if real crash/kill losses justify it and a deliberate local recovery scheme can be verified. |
| Retain audio permanently | Different privacy/ownership model and a playback/archive surface. Outside this capture proposal. |

Mic only, explicit start, no idle tap or wake word, no system-audio APIs. Resampling queues, retry PCM and warm model state exit with the session. Do not log transcripts, filenames that contain thoughts, or PCM. No audio/transcript can flow to normal network paths. Apple-managed downloads may contact Apple's service to fetch assets. That is separate from recognition. The probe exercised local module results with no network-client entitlement and without legacy speech authorization. A physical disconnected run is still needed, since client sandboxing does not audit all OS processes.

The physical mic can pick up nearby people or a speaker. Avoid claims of isolation from physical sound. An authorized app can still face a muted, busy or absent input, bad Bluetooth route, or a device switch. Show readiness from samples, stop safely on discontinuity, and surface recovered words for review. Qualify independent speech presence on quiet, atypical and short speech before rejecting it. Silence, a bad transcript and inability to save are distinct cases. An app-owned no-file guarantee does not describe operating system swap and crash data. See [release and permission research](RESEARCH.md).

## 7. Compatibility and release

Rasc's deployment floor is macOS 14 and the current DMG is arm64. The release uses App Sandbox, Hardened Runtime and ad-hoc signing. It is unnotarized. The default Release build lacks an embedded updater. The updater build embeds Sparkle 2.9.4, pins its framework using a library load constraint, uses separately entitled updater services, and manually checks for updates. The app host has no network-client permission. The mic usage string and audio-input entitlement would be planned changes to both release paths.

Use **Apple silicon, macOS 26+, runtime SpeechTranscriber support, selected locale assets and authorization** for the smallest trial boundary. Gate the API at runtime and validate early M-series Macs. Rasc itself retains the current deployment floor. Speech and Refine have independent availability. If older-OS demand is substantial or the native engine misses quality gates, try a single portable engine before agreeing to support multiple providers.

The lab upgrade changed only CFBundleVersion and the resulting CDHash, with the same bundle ID, location, and entitlements. The original signature returned authorized. The replacement returned not determined. This reproduces a permission discontinuity for a sandboxed fixture. A quarantined clean install and true Sparkle update using test bundles and test notes has yet to qualify the release. Decide whether repeat contextual authorization after an update is acceptable, or whether predictable permission continuity justifies revisiting signing. Keep app-level speech TCC only for a chosen engine that actually needs it. ## 8. Relative scope and roadmap

Markdown export improves downstream ownership and is merged. The MCP feasibility work could improve interoperability and remains deferred pending pairing and distribution validation. Voice can affect every thought a user chooses to capture by speaking. Its greater proximity to the core loop makes this a worthwhile experiment, and raises the cost of false success. Keep existing native validation and onboarding priorities visible while it is studied. [Export evidence](../../docs/validation/export/README.md) · [MCP feasibility](../../docs/LOCAL-MCP-FEASIBILITY.md)

1. **Reviewed dogfood.** One native engine, independent toggle, bounded recovery, explicit review and Keep. Compare typing and system Dictation inside Scratchpad on the same tasks. Use at least a week of voluntary use plus synthetic/specially recorded human sessions across accents, developer/nontechnical situations and motor access needs. Track meaningful corrections and voluntary use locally. Preserve only consented test audio or aggregate observations.
2. **Choose the single engine.** Qualify native speech on natural speech, noise and mixed language, full gamut of mic routes and asset states. Test Portuguese and English separately. Try the best portable comparator if native misses the gate consistently. Use pinned setups and holdout recordings. Stable curated vocabulary bias is a research option if it materially improves results without unwanted substitutions.
3. **Smallest candidate, after approval.** Menu + optional shortcut, a non-key capsule, one selected capture language and engine, memory retry, a dedicated transaction, accessible errors and Undo. Run full release and current Rasc regression gates. Enable automatic Keep only after its semantics and trust outcomes pass.
4. **Later if demonstrated.** Push-to-talk, optionally visible partials, broader language switching and older macOS. Continue to exclude recording archives, meetings, cloud, assistants, system-wide injection and automatic transformation.

## 9. Proposed acceptance gates

| Gate | Measures required before shipping |
|---|---|
| Product | At least 12 people across EN and pt-BR, including at least 3 for whom typing is physically inconvenient. Over 5–7 days, a majority voluntarily uses it in at least two contexts. In intended tasks, median time to usable retained thought improves by at least 20% versus each user's faster baseline, including correction time. Separate short prompts and accessibility results. |
| Fidelity | Holdout of at least 150 natural EN, 150 pt-BR and 100 mixed technical samples across ≥12 voices. For auto-Keep, zero changed negations/uncertainty, invented claims or materially wrong names/numbers on preregistered sentinel cases, and ≥97% substantive acceptance by blinded reviewers on the rest. Report WER and semantic errors separately. Zero in 150 still has an approximate 2% upper 95% error limit, so verify longitudinally. |
| Silence and boundaries | Zero commits on 100 no-speech events including silence, ambient sound, clicks and rapid toggles. ≥99% first/last meaningful-word agreement on 200 physical and fixture boundary trials. Include short, quiet and atypical speech, cold start, modifier-first release, and near-boundary tails. |
| Timing | ≤100 ms p95 delivered shortcut to on-screen frame. ≤300 ms p95 first usable frames on a prepared built-in route, with an initial ≤500 ms cold p95 goal and visible prep feedback. If partials are shown, aim for ≤1.8 s p95 for qualifying speech. ≤1 s p95 short Finish-to-durable-Keep and clear Finishing within 100 ms when waiting. Test supported floor, Bluetooth and thermal load, and refine these product targets after measurement. |
| Persistence and state | At least 1,000 simulated sequences including key-repeat, cancel, interruption, save failure and late events. Exactly one per successful ID and zero for canceled/empty. Preserve full active draft, FTS, undo, retrievability and export. Inject faults before and after commit, including process exit. |
| Energy and privacy | Zero active microphone/taps outside explicit sessions, no app-owned audio files or content-bearing telemetry, and no network dependence for inference after setup. Profile total app + speech services idle and active on M1- and M3-class Macs. Idle delta should be within the noise floor across 60 seconds. Set measured active and retained-memory limits before choosing model warming policy. |
| Native and release | Hands-on first use, allow/deny/revoke/retry, VoiceOver, keyboard-only including cancel, Full Keyboard Access, Reduce Motion, Increase Contrast, all themes, built-in/USB/Bluetooth, contention, device switch, sleep, app switch, fullscreen, Spaces, multiple displays and Stage Manager. Verify exact sandboxed signed DMG, Sparkle update and either permission continuity or clear successful reauthorization. Verify 14/15 gating preserves baseline. |

The proposed candidate earns production implementation only after the review, natural speech and release evidence supports it.
