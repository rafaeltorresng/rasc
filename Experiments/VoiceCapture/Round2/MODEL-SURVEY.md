# Local ASR shortlist · November 2026

## Four different frontiers

The public Hugging Face Open ASR Leaderboard snapshot dated November 20, 2026 (v1.16.2) was read directly from the live tables on November 24. Default English is an average over seven public and two private tasks. The Portuguese column in the separate multilingual table is an error rate on that task, with aggregate multilingual placement depending on language coverage. Neither metric ranks short mic captures with natural Portuguese–English switching. Leaderboard RTFx is server throughput and cannot be used to predict a Core ML or MLX app’s button-to-Keep latency. [Live leaderboard](https://huggingface.co/spaces/hf-audio/open_asr_leaderboard) · [Interspeech methods paper](https://www.isca-archive.org/interspeech_2026/srivastav26_interspeech.html) · [Versioned task definitions](https://huggingface.co/spaces/hf-audio/open_asr_leaderboard/blob/main/init.py) · [Captured rows](results/leaderboard-selected.json)

- **Absolute quality on these benchmarks.** Zoom Scribe v2.1 Pro leads the displayed English table at 4.87% WER. Microsoft Azure Speech September 2026 leads the displayed multilingual table at 3.27% average ER and 2.94% on Portuguese. They establish a comparison point. Rasc’s local and offline requirements exclude service endpoints. [Leaderboard](https://huggingface.co/spaces/hf-audio/open_asr_leaderboard)
- **Open weights.** Musci-ASR-qwen-1019-hf is the highest verified open-weight row in the displayed English default at 5.70%. Its evidence is English-focused. Salesforce SOV-Transcribe-1 scored 5.96% there and 4.69% on Portuguese. NVIDIA’s Nemotron 3.5 Transcribe 30B-A4B is stronger on that PT column at 4.08–4.12%. Both SOV and the 30B model are large mixture-of-experts checkpoints without a measured viable app runtime here. [Musci model](https://huggingface.co/Musci-research/Musci-ASR-qwen-1019-hf) · [SOV model](https://huggingface.co/salesforce-sovereign-intelligence/SOV-Transcribe-1) · [NVIDIA 30B model](https://huggingface.co/nvidia/NVIDIA-Nemotron-3.5-Transcribe-30B-A4B)
- **Consumer Apple Silicon.** Fluid Speech Pro at 6.06% EN default and 4.88% on the PT column has a well-documented native conversion. This is a strong portable result from the public reference configuration. The vendor’s 5.43% over seven public tasks is a different aggregate. Ultra does not have an equivalent published row in this archive. Rumble-2-Flash, Qwen and Granite illustrate additional useful quality/size points. Those scores do not establish equivalent transcripts for the conversions measured here. [Fluid model](https://huggingface.co/FluidVoice-Labs/fluid-speech-pro) · [Fluid Core ML accuracy caveats](https://huggingface.co/FluidVoice-Labs/fluid-speech-pro-coreml) · [Rumble-2-Flash model](https://huggingface.co/Reson8/Rumble-2-Flash)
- **Rasc.** Fluid and Ultra ran in the signed study environment and are the current credible native finalists, with Apple as first-use, ecosystem and fidelity control. Final selection depends on semantics and correction effort on held-out human speech, short capture boundaries, cold load and update behavior. [Local trials](README.md#what-was-measured)

## Screening decisions

| Candidate | Evidence and deployment implications | Decision |
|---|---|---|
| **Apple SpeechTranscriber** | Apple SpeechAnalyzer on macOS 26. Locale fixed per session; OS asset preparation and availability. Native progressive partials and final segments verified in Round 1, tested here in separate yes/no locale groups using local prepared assets. No weight redistribution or third-party inference dependency. [Apple WWDC SpeechAnalyzer](https://developer.apple.com/videos/play/wwdc2025/277/) · [SpeechTranscriber](https://developer.apple.com/documentation/speech/speechtranscriber) | **Study control**, full human dataset. |
| **Apple DictationTranscriber** | Separate SpeechAnalyzer module, including a dictation-specific preset and language availability. Round 1 saw truncation and damaged mixed/short edge cases. The built-in macOS Dictation workflow in Scratchpad is a distinct product baseline. [Apple module](https://developer.apple.com/documentation/speech/dictationtranscriber) · [macOS Dictation](https://support.apple.com/guide/mac-help/use-dictation-mh40584/mac) | Keep Round 1 baseline. Compare real typing and system Dictation in the product-use trial. |
| **NVIDIA Parakeet TDT v3, 0.6B** | 25 European languages including PT and EN, CC BY 4.0. Native Core ML conversion ran in signed Round 1. HF default 7.04% EN, 6.08% PT. [NVIDIA model](https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3) · [Core ML conversion](https://huggingface.co/FluidInference/parakeet-tdt-0.6b-v3-coreml) | Preserve Round 1; test the two adjacent, better-placed derivatives first. |
| **Fluid Speech Pro, 630M** | Multilingual Parakeet TDT derivative, CC BY 4.0. Original NeMo, ONNX, Core ML and MLX paths. Author Core ML is quantized and uses a FluidAudio fork for the appropriate tokenizer and decoder. Native batch tested in verbatim mode with a local directory. Author claims regarding speed and model formatting are separate from the observed measurements. [Original](https://huggingface.co/FluidVoice-Labs/fluid-speech-pro) · [Core ML](https://huggingface.co/FluidVoice-Labs/fluid-speech-pro-coreml) · [MLX listing](https://huggingface.co/FluidVoice-Labs) | **Study finalist**, full human dataset. Quantized and original parity open. |
| **Moondream Parakeet Ultra, 600M** | CC BY 4.0, post-trained on Parakeet v3. Moondream reports gains on noisy and long-form speech. Pinned converted 8-bit Core ML ran in the study fork with the original preprocessing and decoding family plus an alias for its joint decision module. Native app path is batch. [Original and vendor benchmarks](https://huggingface.co/moondream/parakeet-ultra) · [Core ML](https://huggingface.co/FluidInference/parakeet-ultra-coreml) | **Study finalist**, full human dataset. Vendor benchmark gains do not establish spontaneous switching. |
| **Qwen3-ASR 0.6B and 1.7B** | Apache 2.0. Authors offer language identification and offline and streaming inference paths. These Swift/Core ML ports and quantized MLX conversions are independent deployments. The tested MLX Python API used batch and reported language; the Swift VAD-driven option buffers segments; per-runtime streaming parity is open. The 1.7B 4-bit had good clean EN and synthetic PT but scored 12.87% on held PT and garbled key terms in mixed; 0.6B weak on both human PT screening and synthetic mixed. [0.6B model](https://huggingface.co/Qwen/Qwen3-ASR-0.6B) · [1.7B model](https://huggingface.co/Qwen/Qwen3-ASR-1.7B) · [Original runtime](https://github.com/QwenLM/Qwen3-ASR) · [MLX variants](https://huggingface.co/collections/mlx-community/qwen3-asr) · [Core ML Swift path](https://github.com/mattt/AnySpeechRecognizer) | **Benchmarked**. 0.6B stopped after screen; 1.7B completed held. Quantization and native port equivalence unverified. |
| **Nemotron 3.5 Streaming Multilingual, 600M** | OpenMDW 1.1, 35 language settings with 19 marked transcription-ready locales, including explicit pt-BR and English. Non-overlapping cache-aware FastConformer RNNT. NVIDIA reference supports 80/160/320/560/1,120 ms chunks. Apple export has distinct packs and context parameters. Evaluated the Latin 560 ms Core ML pack in auto and a smaller explicit pt-BR spot check. GGUF and Swift/Core ML alternatives exist. [Original card and chunk table](https://huggingface.co/nvidia/nemotron-3.5-asr-streaming-0.6b) · [Apple conversion](https://huggingface.co/FluidInference/Nemotron-3.5-ASR-Streaming-Multilingual-0.6b-CoreML) · [Upstream FluidAudio](https://github.com/FluidInference/FluidAudio) | **Benchmarked synthetic with real paced path**. Retain as a streaming challenger after edge and correction tests. |
| **Granite Speech 5.0 TurboCTC, 470M** | Apache 2.0 base tested in MLX, distinct `-nc` checkpoint carries CC BY-NC-SA and a stronger English leaderboard number. Encoder-only CTC uses a low-cost greedy decoder. Six languages including PT and EN. The benchmark checks what the tested checkpoint generated automatically, even when the wrapper’s result language field stayed `en`. [Open base](https://huggingface.co/ibm-granite/granite-speech-5.0-470m-turboctc) · [NC variant](https://huggingface.co/ibm-granite/granite-speech-5.0-470m-turboctc-nc) · [Native Swift implementation](https://github.com/kylehowells/Granite-MLX) | **Benchmarked**, full human dataset. Strong read EN and warm latency. Weaker held PT means no native app integration in this round. |
| **Cohere Transcribe, 2B** | Apache 2.0, 14 languages. Publisher reports some English + another language switching, without explicit training for it. Selected 4-bit MLX conversion was strict-incompatible with the Python runtime and ran in Swift separately. A Portuguese hint mattered on one controlled example. Approximately 1.51 GB conversion plus runtime loads. [Cohere release](https://huggingface.co/blog/CohereLabs/cohere-transcribe-03-2026-release) · [Pinned conversion](https://huggingface.co/beshkenadze/cohere-transcribe-03-2026-mlx-4bit/tree/104bc4391b5b1a12b040859793d7148525e1a08c) | **Swift smoke only**. Defer until language selection and conversion can be tested on a matched screen. |
| **Whisper Large-v3 and Large-v3 Turbo** | MIT model family plus MIT whisper.cpp. Large-v3 uses the full decoder. Both have local optimized variants and can transcribe PT and EN. Full model on the same fixtures cost more memory and time and still hallucinated on every no-speech control. The defaults have no reliable automatic Keep policy. [Large-v3](https://huggingface.co/openai/whisper-large-v3) · [Turbo](https://huggingface.co/openai/whisper-large-v3-turbo) · [whisper.cpp](https://github.com/ggml-org/whisper.cpp) | **Synthetic reference**; Turbo data preserved from Round 1. |
| **Phonon 2.5** | New multilingual 25-language Parakeet derivative, distinct from its English-only sibling. Current English default scores are 7.16% and 7.05% respectively. CC BY 4.0. Small MLX builds and local Core ML supply make this a useful efficiency challenger. Current evidence did not establish a benefit over either tested portable finalist on PT thought capture. [Original](https://huggingface.co/FermionResearch/Phonon-2.5) · [FluidAudio](https://github.com/FluidInference/FluidAudio) | Defer to the next inexpensive screen if asset size becomes a deciding cost. |
| **QVAC TranscribePsy 250M EU-sub** | Apache 2.0, eight target languages including PT and EN. Official card points to mobile-friendly GGUF and a developer Core ML pack. 8.78% PT on the public table; attractive for footprint and lower-powered Macs if quality is sufficient. [Model and runtime](https://huggingface.co/qvac/TranscribePsy-250M-EU-sub) | Defer. Good size challenger after stronger matched tests. |
| **Voxtral Mini 4B Realtime** | Apache 2.0. Causal realtime model covers English and Portuguese. Vendor describes configurable delay; public Apple conversions require their own memory, streaming and fidelity validation. A larger stack than cache-aware Nemotron 600M. [Mistral model](https://huggingface.co/mistralai/Voxtral-Mini-4B-Realtime-2602) · [Launch post](https://mistral.ai/news/voxtral-transcribe-2) | Defer as alternative stream reference if Nemotron cannot pass edges or PT. |
| **Omnilingual ASR v2** | New 300M through 7B CTC and LLM variants. Apache 2.0 cards. Example PT results 14.29% (CTC 300M), 7.04% (LLM 1B) and 5.18% (LLM 7B). The family prioritizes broad language coverage. [300M CTC](https://huggingface.co/hf-audio/omniasr-ctc-300m-v2) · [7B LLM](https://huggingface.co/hf-audio/omniasr-llm-7b-v2) | Defer. Smaller models did not offer enough PT evidence; larger variants lack a demonstrated native advantage. |
| **Granite Speech 5.0 2B** | Apache 2.0, 6.68% EN default. Could be a larger quality reference, but does not inherit the 470M CTC deployment or solve its measured PT trade-off automatically. [IBM model](https://huggingface.co/ibm-granite/granite-speech-5.0-2b) | Defer. |
| **PT-specific Nemotron fine-tunes** | `ottema/nemotron-3.5-asr-ptbr` OpenMDW 1.1 reports quality gains on PT domains including CORAA. Need to establish overlap, a deployable conversion, and retention of English/mixed ability. [PT-BR model](https://huggingface.co/ottema/nemotron-3.5-asr-ptbr) | Defer. Good diagnostic if multilingual finalists fail in PT. |
| **TheWhisper Large-v3 Turbo** | Additional candidate discovered in the board. 6.74% EN and 3.85% PT, CC BY 4.0 card. Author’s Apple SDK claims macOS 15+, Core ML and live streaming. Assets are target-specific packs with a separate SDK, and the benchmark conversion and redistribution path need source/manifest review before measured parity. [Model, benchmarks and SDK setup](https://huggingface.co/TheStageAI/thewhisper-large-v3-turbo) · [Apple SDK](https://github.com/TheStageAI/AppleSDK) | **Highest-priority additional screen** when the native pack can be staged and audited for offline use. No local run this round. |
| **Rumble-2-Flash, Musci-ASR** | Rumble-2-Flash is an Apache 2.0 ~0.5B multilingual open-weight model at 6.60% EN and 6.46% PT. No audited ready Swift conversion identified. Musci is an Apache 2.0 Qwen 1.7B derivative with strong vendor English scores and a newer GGUF conversion. Its benchmark-driven training and English emphasis merit an independent PT slice before native packaging. [Rumble](https://huggingface.co/Reson8/Rumble-2-Flash) · [Musci](https://huggingface.co/Musci-research/Musci-ASR-qwen-1019-hf) · [Musci GGUF](https://huggingface.co/cstr/musci-asr-qwen-1019-GGUF) | Defer integration; keep on the watch list. |
| **SOV / NVIDIA 30B** | SOV has 26.6B total parameters with 4.6B active. The latter is 30B total with 4B active. Active count is not the amount of memory needed to load weights. Current serving and model supply do not give a practical embedded reference for the target 18 GB Mac. [SOV card](https://huggingface.co/salesforce-sovereign-intelligence/SOV-Transcribe-1) · [NVIDIA card](https://huggingface.co/nvidia/NVIDIA-Nemotron-3.5-Transcribe-30B-A4B) | Leaderboard quality references only. |

## Inference infrastructure

- **AnySpeechRecognizer** was inspected at `06e0842b164bdb7ddc16f365757a807980745bf8`, with prerelease-era API maturity around the October 28 v0.1.0 release. Apache 2.0, Swift tools 6.2, macOS 26, Core ML with Swift Hugging Face asset handling. Reuses Apple-style transcriber and analyzer shapes. Supports Parakeet Ultra and both Qwen sizes. An eight-second Parakeet window can provide buffered results; API shape doesn’t make it a cache-aware live engine. Useful for a targeted parity and maintenance comparison if Ultra wins. No new common production abstraction is needed just to run the study. This package was inspected, not benchmarked. [Pinned Swift source](https://github.com/mattt/AnySpeechRecognizer/tree/06e0842b164bdb7ddc16f365757a807980745bf8) · [Author discussion](https://huggingface.co/blog/anydecisionmodel)
- **speech-swift** was inspected at `8effd8f8cbcb6aa1b9355cc6120c2290f05eafd7`. Tested release v0.0.29 for the Cohere smoke with locally staged MLX weights. Apache 2.0, Swift 6 tooling, macOS 15 package floor. It supplies model-specific ASR products and CLI from a broader MLX / Core ML speech package with Qwen, Parakeet, Nemotron, Whisper and Cohere paths. Its exact model, packed engine, VAD/stream path, transitive dependencies, cache and downloads need review if selected. The v0.0.29 Cohere experiment does not validate all engines or a sandboxed app. [Source](https://github.com/soniqo/speech-swift/tree/8effd8f8cbcb6aa1b9355cc6120c2290f05eafd7) · [Tested release](https://github.com/soniqo/speech-swift/releases/tag/v0.0.29)
- **FluidAudio** proved the shortest path to current Core ML candidates in signed sandbox builds. Apache 2.0 Swift package (supported version and dependencies vary by revision and family). The study pins the model author’s fork for Pro and adapts a tested Ultra pack. The separate Nemotron app uses upstream v0.18.4. A production dependency should select one verified engine path and carry a pinned asset manifest. The study bypasses general download APIs. Replacing the author fork with upstream would require output and cold-load parity checks. [FluidAudio](https://github.com/FluidInference/FluidAudio) · [Study fork](https://github.com/altic-dev/FluidAudio/tree/386f7195670b77f2954c7ee143ec63fcb50b6c3b)
- **MLX Audio** Python was useful for precision screening and reject-first comparisons. MLX is Apple Silicon GPU oriented. It can use more process memory than a native Core ML pack. Strict load matched the tested Qwen and Granite assets but caught the Cohere mismatch. Native MLX Swift ports, Core ML and quantized packs deserve comparison on identical PCM before choosing one. GitHub project changes cannot be inferred from the pinned Python result. [MLX Audio](https://github.com/Blaizzy/mlx-audio) · [MLX Swift](https://github.com/ml-explore/mlx-swift) · [Exact Python package set](results/mlx-requirements.txt)
- **WhisperKit and C++ runtimes**. WhisperKit offers Core ML with local streaming-style transcription and an optional downloader. whisper.cpp provides GGML/Metal, direct file loading and an auditable compiled runtime. Our C++ run exercised batch, and streaming demos that recompute windows are a different path. sherpa-onnx advertises a compact offline ASR stack with transducer/CTC and model-specific streaming; it may be worthwhile for QVAC or ONNX derivatives if a selected model warrants its additional runtime. [WhisperKit](https://github.com/argmaxinc/WhisperKit) · [whisper.cpp](https://github.com/ggml-org/whisper.cpp) · [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx)

Before production, audit the exact code and weight rights, bundled notices, dependency changes, reproducible weights, and local cache behavior. Core ML compilation does not establish model parity, sandbox fitness across machines, or a fixed allocation to the Neural Engine. Local assets and signed current sandbox runs demonstrate feasibility for the tested builds. [Study attribution](Study/NOTICES.md) · [Release findings](README.md#privacy-and-distribution)
